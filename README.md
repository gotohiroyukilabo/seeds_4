# 抗体工学を起点とした新規創薬シーズのリサーチ

## 目的

部署内で提案する、新しい抗体医薬品の創薬シーズテーマを探索する。
新規標的の発見そのものよりも、**抗体のフォーマットや機能の設計によって、既存の治療や開発候補の課題を解決すること**を重視する。

科学的な新規性だけでなく、開発可能性と臨床的な価値を評価し、部署内で議論・提案できる具体的なテーマにまとめる。

## 基本方針

- **オンコロジー領域・免疫領域に注力する。** どちらか一方、または両方を対象として、創薬シーズテーマを探索する。
- **抗体工学を主軸にする。** 既知の標的でも、抗体設計により新しい治療価値を生み出せる場合は対象とする。
- **アンメットニーズを起点にする。** 治療選択肢が乏しい疾患や、既存治療では十分な効果が得られない患者セグメントを優先する。
- **開発可能性を考慮する。** 有効性の仮説に加え、安全性、製造、薬物動態、評価モデル、臨床開発の実現性を検討する。
- **過去の失敗を着想に変える。** 開発中止品や期待した成績を得られなかった候補について、その弱点を抗体工学で補えるかを検討する。
- **事実と仮説を分ける。** 公開情報で確認できた内容、そこからの解釈、提案する設計仮説を明確に区別する。

## 探索するアイデアの方向性

以下は探索の出発点であり、採用済みのテーマや実現性を確認した設計ではない。

| 方向性 | 検討するアイデア | 主に確認する論点 |
| --- | --- | --- |
| 新しい抗体フォーマット | 「I型抗体」のような新しい構造・フォーマットを利用する | 構造と作用機序、既存フォーマットとの差、設計・製造の実現性 |
| 環境に応じた結合・活性の制御 | pH差などを利用し、腫瘍微小環境で結合や活性が強くなる抗体を設計する | 正常組織との選択性、環境のばらつき、体内での制御の成立性 |
| 多重特異性による選択性の向上 | 二重特異性などを利用し、狙った細胞・組織への作用を高める | 抗原の共発現、結合条件、正常組織への作用、有効性と安全性の両立 |
| 開発中止候補の再設計 | 毒性などが課題だった候補の作用機序を、別の抗体設計で活用する | 中止理由の確度、設計で改善できる原因か、同じ問題が再発する可能性 |

※「I型抗体」は依頼時の表現を保持している。具体的な構造・文献・正式名称を確認してから調査対象を定義し、特定のフォーマットと同一視しない。

### 発想の例

「薬効は期待されたが、正常組織への作用による毒性が課題となった候補」に対し、二重特異性や環境依存的な結合を導入することで、病変部への選択性を高められないかを検討する。

その際、**設計を変えれば毒性が下がると決めつけず、毒性の原因と設計変更による改善の根拠を確認する。**

## 疾患・患者セグメントの選び方

オンコロジー領域・免疫領域のどちらか、または両方から対象疾患・患者セグメントを選ぶ。抗体工学による解決策が成立し、アンメットニーズが高い対象を優先する。

- 標準治療が存在しない、または治療選択肢が限られる疾患
- 既存治療に抵抗性・不応性となった患者群
- 毒性や併存疾患などの理由で、既存治療を受けにくい患者群
- 特定の抗原発現や病変環境などにより、設計の利点を検証しやすい患者群

疾患名だけでなく、可能な範囲で治療ライン、既治療歴、バイオマーカー、既存治療の限界まで具体化する。

## 各テーマで調べること

1. **臨床課題：** 誰の、どの未解決課題を解決するのか。現在の治療では何が不足しているのか。
2. **抗体設計：** どの構造・機能を変え、それによりどのような作用を期待するのか。
3. **先行事例：** 関連する論文、特許、開発品、臨床試験、開発中止例には何があるか。
4. **差別化：** 既存治療や競合候補に対して、どの点で臨床的な価値を示せるか。
5. **開発可能性：** 発現・精製、安定性、凝集、薬物動態、免疫原性、安全性などに重大な懸念がないか。
6. **検証方法：** 設計の利点を示すために、どの実験系、比較対照、評価指標が必要か。
7. **臨床への接続：** 対象患者を選別できるか。バイオマーカーや薬効評価の方法を設定できるか。
8. **残る不確実性：** 成立に必要な条件は何か。どの結果が出たらテーマを見直すか。

## 開発中止例の扱い

- 中止の事実、時期、開発段階、企業が公表した理由を確認する。
- 有効性不足、毒性、製造上の問題、事業上の判断などを区別する。
- 理由が非公開・不明な場合は推測を事実として扱わない。
- 抗体工学で改善できる課題と、標的や作用機序そのものに由来する課題を見極める。
- 原候補との比較で、改善を実証するために必要なデータを示す。

## 情報収集と記録

論文、臨床試験登録、企業の公式発表、学会発表、特許などの一次情報を優先する。開発状況や標準治療など変化する情報は、調査時点で確認する。

記録には出典のURLまたはDOI、公開日、確認日を付ける。前臨床データと臨床データを区別し、根拠が不足する点は未確認事項として残す。

## 成果物

調査結果、候補テーマの比較一覧、有望テーマごとの提案メモは、プロジェクトの作業ディレクトリ内にMarkdown形式（`.md`）のファイルとして保存する。

本プロジェクトで作成したファイルはすべてGitでコミットし、GitHubのリポジトリの`main`ブランチにpushする。既存ファイルを更新した場合も、変更内容をコミットして同じブランチにpushする。

### 候補テーマの比較一覧

対象疾患・患者セグメント、アンメットニーズ、抗体設計、先行事例、差別化、開発上のリスクを一覧化する。臨床的価値、科学的根拠、設計の独自性、開発可能性を総合して優先順位を付け、その理由を示す。

### 有望テーマごとの提案メモ

各メモには以下をまとめる。

- テーマ名と提案の要旨
- 対象疾患・患者セグメントと未解決の臨床課題
- 抗体設計と作用機序の仮説
- 先行事例・競合・関連する開発中止例
- 期待する利点と、それを支持する根拠
- 開発可能性、主要なリスク、未確認事項
- 初期検証の実験案と、継続・見直しの判断基準
- 参照資料と情報の確認日

## 最終的に目指す状態

「面白い抗体技術」の紹介にとどまらず、**どの患者の課題を、どの抗体設計で、なぜ解決できると考えるのか、そして次に何を検証すべきか**を説明できる状態にする。
